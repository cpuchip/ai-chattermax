## What happened

Built DM support — "the CT2 context surface." The schema already had `dms` +
`dm_participants` (kind `user_user` | `user_persona`) and `messages.dm_id`, so the
work was wiring, not new tables. **Key insight: a DM is just another "channel"** —
the multiplexed gateway and the persona-host turn loop are channel-agnostic, so
most of the feature was generalizing room-only assumptions to room-or-dm.

- **store/dms.go**: `OpenDMWithPersona` (find-or-create; requires `dm_enabled`)
  + `OpenDMWithUser`, `ListDMsForUser` (summarized by the *other* participant),
  `User/PersonaCanAccessDM`, `PersonaDMs`, `InsertDM{User,Persona}Message`,
  `ListDMMessages`.
- **httpapi**: `GET/POST /api/dms`, `GET /api/dms/{id}/messages`, and persona-key
  `GET /api/persona/dms` (so a host subscribes to its DM threads).
- **gateway**: `canAccess` → `channelKind` (returns room|dm); `handleMessage` +
  `sendHistory` route to the room vs dm store by kind. Presence/broadcast
  unchanged (channel-keyed regardless).
- **persona-host** (workspace root): `fetchDMs` + `subscribeNew` — fetches
  `/api/persona/dms` alongside rooms and subscribes; the existing humans-only turn
  loop handles DM messages exactly as room messages.
- **frontend**: a Direct Messages section in the sidebar (click a dm-enabled
  persona to DM it; a New-DM picker for members + personas); RoomView/Shell render
  the active channel (room OR dm) with a DM header; `send` routes to the active
  channel; `selectDM`/`openDMWith*` actions.

## Verification (prod, end-to-end)

- REST: opened a human↔persona DM (claude-codetest → a dm-enabled "DMBot" I own),
  `/api/dms` listed it, `/api/persona/dms` returned it for the persona key.
- **Live**: ran a local persona-host for DMBot → it joined the DM thread → I
  posted privately → DMBot replied in the DM in ~12s ("Yep, receiving you loud and
  clear! Direct messages seem to be working perfectly."). Cleaned up after (revoked
  the test key via AXR2; killed the host).
- human↔human shares the identical gateway/store routing (only participant type
  differs — `OpenDMWithUser`); REST verified, build-covered.
